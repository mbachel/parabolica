# 0005: Decisions from the Matthew and Soumil meeting

**Decided:** 2026-09-24 (evening meeting)
**Sources:** Meeting Agenda 2026-09-24; Master Plan; Infrastructure Plan; Backend Spec, section 4

## 1. Name: Parabolica

**Status:** Accepted (open decision 1, closed)

**Decision:** The project is named Parabolica. The name goes on everything: GitHub repo, local repo folders, domain and the app itself. No mixing with the old name.

**Why:** Another app already uses "RaceIntel."

**Rejected:** RaceIntel.

**Consequences:** The rename and repo reorganization happen together in Phase 0. How it was carried out is in 0006.

## 2. Hosting: all Azure, on Container Apps

**Status:** Proposed ("most likely" at the meeting; open decision 2 is not formally closed)

**Decision:** Production runs entirely on Azure, behind Cloudflare:
- Container Apps for the backend, with at least one copy always running
- Container Apps for the frontend, scaling to zero when unused
- PostgreSQL Flexible Server for the database

**Why (Infrastructure Plan, section 1.9):**
- It's the cheapest option that stays managed: about $26 a month after free credits, about $57 for the first year.
- It doesn't charge for a load balancer.
- It barely charges while the backend waits between races.
- The backend can't scale to zero, because the Polling Service has to keep running during race sessions.

**Rejected or not chosen:** Full AWS with containers and a load balancer (about $61 a month), AWS or Azure Kubernetes, hybrid setups, and the smaller providers (full list with prices in Infrastructure Plan, section 1).

**Still open:** The Infrastructure Plan also suggested running one AWS server first for AWS experience, then moving to Azure. That wasn't decided. Cost split between the two of us is also open.

**Consequences:** Once accepted, this replaces 0004, section 2. Terraform targets Azure (azurerm) plus Cloudflare. The homelab is not a production host (0007, section 5).

## 3. "Lap-time charts" become "race line charts"

**Status:** Accepted as a direction, details open (open decision 4 stays open)

**Decision:** The charts feature is renamed from "lap-time charts" to "race line charts," if that turns out to be possible.

**Still open:** What "race line" means. A lap-by-lap running-position chart works with the data we have: NASCAR's lap-time data has every car's position on every lap. Car paths drawn on a track map need car coordinates, which NASCAR doesn't publish. Live vs historical and the visual are also undecided.

## 4. F1 data: the free official F1 live-timing stream

**Status:** Accepted (open decision 5, closed)

**Decision:** F1 data comes from the free streams of the official F1 live-timing feed (SignalR). We accept having no live telemetry.

**Why:** It's free and live. The free streams include timing, positions in the running order, gaps, tyre stints, track status and race control messages. Live car telemetry and car coordinates need an F1 TV login.

**Rejected:** The paid live APIs (OpenF1 Sponsor, Sportmonks, Sportradar and others) and the delayed free sources as the live source. Full comparison in Backend Spec, section 4.

**Consequences:**
- The feed is unofficial with no public API terms, and formula1.com allows personal, non-commercial use only. It can break when F1 changes access, as it did in 2025.
- The ready-made .NET library for this feed, UndercutF1.Data, is GPL-licensed, which conflicts with the MIT license (section 6). We need our own client or a permissively licensed one.
- The design mirrors the NASCAR pattern: an F1 folder beside the NASCAR one, admin-triggered imports, raw JSON storage and cached reads (Backend Spec, section 4).
- Telemetry for past sessions may still be possible later from F1's post-session archive. That isn't decided.

## 5. Tracking tool: Jira Free

**Status:** Accepted (open decision 6, closed)

**Decision:** Work is tracked in Jira on the Free plan. This replaces GitHub Issues.

**Why (Meeting Agenda, section 2):**
- It's free for our team size.
- It has real sprints and a backlog.
- It links to GitHub through a free official app.
- It has an official Claude connector.
- It's the tracker that shows up most in job postings.

**Consequences:** The Free plan allows 100 automation runs a month across the site and has no per-user permissions. How Jira was set up is in 0006.

## 6. License: keep MIT

**Status:** Accepted (open decision 7, closed)

**Decision:** The code stays under the MIT license.

**Why:** If someone copies the project and sells a paid version, nobody is going to use a paid version over a free one.

**Rejected:** Apache, MPL, GPL, AGPL and non-commercial licenses such as PolyForm Noncommercial.

**Consequences:**
- No GPL or other copyleft dependencies in the code, including UndercutF1.Data (section 4).
- The track map images keep their own Creative Commons licenses and credits. MIT covers the code only.
- NASCAR and F1 data sources are non-commercial regardless of the code license (Reference, section 6).

## 7. Phase 1 includes upgrading to current, patched versions

**Status:** Accepted

**Decision:** Phase 1 upgrades the frontend, backend and database to current, patched versions (Frontend Spec 1.1, Backend Spec 1.11).

**Why:** Security. The frontend framework had shipped several critical remote-code-execution fixes since the version in the repo, and the backend runtime was missing 48 security fixes.
